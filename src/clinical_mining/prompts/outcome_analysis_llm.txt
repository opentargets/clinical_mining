ROLE & TASK
Classify clinical trial outcomes from PubMed abstracts for Open Targets. You receive all abstracts for one trial; consolidate across them to identify every distinct outcome tested. Set "id" to the trial's NCT ID.
TRIAL CONTEXT
Alongside the abstracts you get a brief trial description and phase from the registry — what the trial was designed to test (drug(s), condition(s), design). Use it as background for terse abstract language, and for the RELEVANCE CHECK below. Either field may read "Not provided.", meaning the value was missing from source data, not that the trial lacks a design. Treat "Not provided." as absence of information: never reason about, quote, or infer from it.
WHAT IS AN OUTCOME
An outcome is identified by exactly one thing: its key = (therapies, conditions), normalized and canonically ordered.
- therapies: one or more drugs evaluated together as a single regimen
- conditions: one or more conditions that regimen's verdict applies to
- conclusion and primary_endpoint are single values *resolved for* the key, NOT part of its identity. A key with five different endpoint results is still ONE outcome — one governing endpoint, one conclusion, one row. Five conclusions never mean five rows.
The key (therapies, conditions), normalized and canonically ordered, is the sole identifier of an outcome. The same key can never appear twice — not for different conclusions, abstracts, or quotes. If two rows share a key, keep one and discard the other's evidence.
Drug requirement. Every outcome must name at least one real, named drug/intervention — the sole exception is the trial-level irrelevance row defined in the RELEVANCE CHECK, which carries empty therapies. No drug named anywhere → empty outcomes list. A non-drug component (radiotherapy, device) can sit in therapies alongside a drug but never substitutes for one.
Other core rules:
- Populate a field only if explicitly stated. Prefer omitting a therapy/condition over guessing, but never fall back to inconclusive, safety_tolerability, or no_results just because a verdict is hard to read once the key is valid.
- Control arms (placebo, vehicle, active comparator, standard-of-care) get no outcome. A background therapy the experimental arm also receives belongs in that arm's regimen.
RELEVANCE CHECK (run first, before anything else)
If Trial Description reads "Not provided.", skip this check — no baseline exists, so irrelevance can't be judged. Treat every abstract as relevant and go to THE GATE. Don't judge relevance on phase alone ("Phase 1" is too generic).
Some abstracts are linked by a bad PMID/NCT and aren't about this trial at all (wrong drug, disease, or population; a review, unrelated case report, or a different company's compound). This differs from gate failure below: a gate-failing abstract IS about this trial (e.g. a biomarker substudy of the same participants) but reports no drug administration.
When a Trial Description IS provided, compare each abstract to it (and phase, if given). If it doesn't plausibly describe the same drug(s), condition(s), and population, mark it irrelevant and discard it completely — don't use it for extraction, synonyms, or naming.
If a Trial Description was provided and EVERY abstract is irrelevant, stop — don't run Passes A–F. Emit exactly one outcome: therapies [], conditions [], primary_endpoint null, conclusion inconclusive, evidence_quote a verbatim excerpt from the trial description stating what the trial was designed to test, source_pmid null, outcome_confidence reflecting how sure you are the abstracts are unrelated (typically 0.9+ when a clearly different drug and disease). This is the only outcome for the trial; don't add or merge any other row. (This is the single documented exception to the rule that only a no_results row may have a null primary_endpoint.)
If the Trial Description was NOT provided, this trial-level row can never be produced — fall through to the ordinary procedure and the rule that an empty outcomes list is returned if no drug is named anywhere.
If at least one abstract is relevant, discard only the irrelevant ones and proceed with the relevant abstracts.
THE GATE
Per relevant abstract: did it give a named drug to participants and report what happened?
- Yes, with an efficacy result → contributes to an outcome.
- Yes, but only safety/tolerability/MTD/PK/immunogenicity → contributes an outcome, resolving to safety_tolerability.
- No (biomarker, correlative, natural-history, baseline-characteristics, methods papers) → contributes nothing; use only for synonyms/naming. Exception: if the abstract IS this trial's own primary report but has no readout yet (protocol/design/rationale, ongoing, or terminated pre-readout), it yields a single no_results outcome.
safety_tolerability, inconclusive, and no_results all describe a drug that was given but produced no efficacy verdict, and must be kept distinct: safety_tolerability when the only readout was safety/tolerability/MTD/RP2D/PK-PD and efficacy was never assessed; inconclusive when efficacy WAS assessed but the result is genuinely ambiguous; no_results when no readout of any kind exists yet (protocol, ongoing, or terminated pre-readout). None of the three means "this abstract isn't about treatment," and none substitutes for the trial-level irrelevance case above.
PROCEDURE
Apply the Relevance Check first; if it emits the single empty-outcome row, stop. All passes below use only relevant abstracts. Don't attach evidence or write a row until Pass C is done.
A. Therapies. Find the drug(s) administered across all relevant abstracts. None anywhere → stop, empty list.
B. Candidates. Drop gate-failing abstracts. List every candidate (therapies, conditions) pair per the split/combine rules (duplicates expected). Normalize: one name per disease, therapies and conditions each sorted alphabetically, compared case-insensitively.
C. Collapse to unique keys. Write out the distinct keys and count them ("2 keys → 2 rows"). This count is fixed; nothing after can add a row. Re-check: subgroups wrongly merged into a parent; dose/route/formulation/schedule arms wrongly split; unnormalized duplicates.
D. Resolve one conclusion per key — forced two-step, then grounded classification.
Do this for EVERY key from Pass C, no matter how many or few endpoints it reports. A single-endpoint key runs the two-step trivially (one line in, one row out); a multi-endpoint key must not skip it.
  Step 1 — Inventory the endpoints (NOT rows). List every endpoint/result reported for this key across the pooled abstracts: primary, secondary, exploratory, surrogate, and safety endpoints; every row of a GRADE / "summary of findings" table; every forest-plot estimate or pooled comparison. Writing an endpoint on this list NEVER creates a row — the list exists only to be collapsed. A table with N endpoint-rows becomes N inventory lines here, never N output rows. The table is never rows.
  Step 2 — Name the single governing endpoint, and state where it came from, per PRIMARY ENDPOINT's "Many endpoints, one verdict" ordering: (1) a stated pre-specified primary efficacy endpoint; else (2) the endpoint the authors foreground in their own concluding statement / abstract conclusion — for a review or meta-analysis this is the "Authors' conclusions" statement, NOT the summary-of-findings / GRADE table; else (3) the hardest clinical endpoint reported (e.g. all-cause mortality over a surrogate or a lone adverse-event count). This choice is now FIXED — the verdict is resolved from this endpoint's result alone.
  Step 3 — Ground the verdict, then classify (in this order). First name the governing measure. Then find and quote the governing endpoint's OWN reported result (the verbatim span stating what happened to that measure — e.g. whether all-cause mortality was reduced). Then classify the conclusion FROM THAT RESULT, via COMPARATOR TYPE and CONCLUSION CLASSIFICATION. Do not classify from an overall impression of the paper or from any other endpoint.
    - Every other endpoint from Step 1 is discarded: no row, no mention, and NO influence on the verdict. A positive secondary or exploratory result does NOT lift the verdict — it cannot turn a null or failed governing endpoint into efficacy/effectiveness. A harm among the discarded endpoints does NOT set the verdict and is NOT safety_failure unless the arm/trial was actually halted for it (the safety_failure gate).
    - Efficacy assessed but the governing result is ambiguous → inconclusive (still name the measure). No efficacy assessed at all → safety_tolerability (name the governing safety measure). No readout of any kind yet → primary_endpoint null, conclusion no_results.
  Reconcile before moving on: "N endpoints → 1 row." N (the Step-1 count) is never the number of rows.
E. Evidence per key. The Step-3 quote IS the evidence: one verbatim span reporting the governing endpoint's result, plus its source_pmid. It must be about the governing endpoint, not a secondary one. Discard other supporting quotes.
F. Final check. Delete (never patch) any row where therapies/conditions is empty/placeholder (outside the trial-level row); the key duplicates another (merge to the governing-endpoint row per Pass D — do NOT let a discarded endpoint's row survive); a disease has two names across rows (pick one, re-run duplicate check); or the row came from a gate-failing/irrelevant abstract. Catalogue test: if two rows share a key and differ only in primary_endpoint (or conclusion), the Pass D collapse was skipped — merge to the single governing endpoint via Pass D and emit one row. Grounding test: confirm the conclusion follows from the governing endpoint's quoted result and from nothing else — if the quote is about a secondary endpoint, or the category was driven by a different endpoint than primary_endpoint names, re-resolve. Disproof tests: for safety_tolerability, assert "no efficacy result exists for this key" — any response rate, disease-measure change, comparison, or activity/benefit claim disproves it → re-resolve under the efficacy axis (step 5) (or inconclusive). For inconclusive (non-trial-level), assert "efficacy was assessed but no verdict is resolvable" — a clear verdict → the efficacy axis (step 5); no efficacy assessed at all → safety_tolerability. For no_results, assert "no readout of any kind exists" — any safety/PK/MTD result → safety_tolerability; any efficacy result → the efficacy axis (step 5) or inconclusive. Endpoint/conclusion consistency: only a no_results row (or the trial-level row) may have null primary_endpoint; every other row must name its governing measure. On any disagreement, re-resolve rather than patching one field. Finally, confirm row count = key count from Pass C.
SPLIT VS. COMBINE
- Combine: therapies/conditions reported as one regimen with one combined result (sort therapies alphabetically).
- Split: arms with separate results, even if compared ("A vs B vs placebo" → outcomes for A and B only).
- Head-to-head: both active arms get their own outcome (winner effectiveness, loser ineffectiveness).
- Split on the key only — never on different abstracts, quotes, years, or timepoints.
- Same drug(s) differing only in dose/route/formulation/schedule → one outcome; primary endpoint met if met in any such arm.
- Conditions: split if results are per-condition, combine if one verdict covers both.
- Basket/multi-cohort: one outcome per indication, each on its own result, even if the formal primary was on the pooled population.
- Subgroup-level disease results (e.g. per histology) are their own condition, not collapsed into the parent.
- A condition needs at least one reported finding (efficacy, or safety/PK/MTD if that's all) to be included.
- Meta-analyses / systematic reviews / pooled analyses: one such publication usually reports the SAME key against several comparators and endpoints. Still ONE outcome per key — never one row per pooled comparison, included study, forest-plot estimate, or endpoint. Whatever the drug was measured against (placebo or an active drug) is a reference, not a separate experimental therapy, so it gets no outcome of its own. Consolidate to one assessed row (comparator type per COMPARATOR TYPE, governing measure per PRIMARY ENDPOINT). A GRADE "summary of findings" table lists one row per endpoint by design (mortality, hypoglycaemia, infection, etc. side by side) — do NOT mirror it. The whole table is one outcome: run the Pass D two-step, pick the governing endpoint, and emit a single row.
PRIMARY ENDPOINT
- A primary efficacy endpoint alone sets the verdict, overriding secondary/exploratory results and optimistic framing — even for small/terminated/underpowered trials.
- Identify it from the stated objective, however phrased ("the purpose was...", "we sought to..."), not just the word "primary" or order of mention in Results.
- If the trial posed no primary efficacy endpoint (primary was safety/PK/MTD, or none identifiable), any reported efficacy result sets the verdict. Silence on efficacy everywhere → safety_tolerability (if a safety readout exists) or no_results (if none does).
- The endpoint defines the measure, not the population — apply it per indication in basket trials.
- Interim + final analyses of one key are one outcome, resolved on the final report.
- Conflicting co-primary endpoints for one key → mixed, one row (name both, separated by "; ").
- Name the governing measure plainly (e.g. "objective response rate," "5-year disease-free survival"), not "primary endpoint." For safety_tolerability, name the safety/dose-finding measure the same way. Only no_results (and the trial-level row) leaves it null.
- Many endpoints, one verdict. When a source reports several endpoints for one key (common in reviews and multi-outcome trials: mortality, incidence, surrogates, adverse-event tallies side by side), your job is to determine the paper's single MAIN CONCLUSION about the drug — not to catalogue every endpoint reported. Execute this as the Pass D two-step: inventory all endpoints, then name the one governing measure. Decide the governing measure in this order: (1) if a pre-specified primary efficacy endpoint is stated, it sets the verdict (and still overrides an optimistic authors' spin, per the rule above); (2) otherwise, take the verdict the authors themselves foreground in their concluding statement / abstract conclusion — the finding the paper is actually about, the one it leads with or frames as its takeaway; for a review or meta-analysis this is the "Authors' conclusions" statement, NOT the summary-of-findings / GRADE table; (3) only if the authors state no clear bottom line, fall back to the hardest clinical endpoint reported (e.g. all-cause mortality over a surrogate or a lone adverse-event count). A secondary or exploratory endpoint the authors do not treat as their main finding never overrides (1) or (2), and — critically — never contributes to the verdict at all: a positive secondary does not upgrade a null or failed governing endpoint. A harm reported among the endpoints does not set the verdict and is not safety_failure unless the arm was actually halted for it. Selecting the governing measure means every other endpoint gets NO row and no mention — not one row per endpoint with one flagged primary. You emit a single row whose primary_endpoint is the governing measure and whose conclusion is that measure's result. A predefined secondary or exploratory endpoint never earns its own row.
COMPARATOR TYPE
- Active comparator (head-to-head/non-inferiority) → effectiveness / ineffectiveness. A named active drug as reference — an approved standard-of-care AGENT (e.g. metformin) or any marketed drug — IS an active comparator; don't default it to efficacy/lack_of_efficacy just because the drug beat placebo elsewhere.
- Placebo, no comparator, or historical/threshold control (incl. all single-arm trials, and add-on designs where both arms share a background therapy) → efficacy / lack_of_efficacy.
- Strategy/intensity/target comparators are NOT active drug comparators. When the reference is an intensity, target, or overall management STRATEGY rather than a distinct drug — e.g. intensive vs conventional/standard control, tight vs usual care, treat-to-target vs routine management, aggressive vs standard-of-care approach — treat it as an inactive/threshold reference → efficacy / lack_of_efficacy. Reserve effectiveness / ineffectiveness for when the reference is itself a named, distinct active drug or regimen.
- If one pooled source reports the same key against BOTH an inactive control AND an active DRUG comparator, treat the key as active-comparator: beating placebo but not superior to (or failing non-inferiority vs) an active standard-of-care drug is ineffectiveness — not lack_of_efficacy, not mixed. (A strategy comparator does not trigger this; it stays on the efficacy/lack_of_efficacy axis.)
- Undeterminable → default efficacy/lack_of_efficacy, lower confidence.
- One comparator determination per key. safety_tolerability is polarity-neutral and doesn't use this.
MULTIPLE RESULTS, SAME KEY
Always resolve to one row, never one per result/quote/abstract. Agreement → one row, higher confidence. Genuine conflict on category → mixed. Exceptions that are NOT conflicts: safety_failure always overrides everything; dose/route/formulation/schedule variance; a resolved verdict in one abstract plus silence in another; a safety/tolerability-only readout alongside an efficacy readout for the same key (efficacy governs → efficacy category or inconclusive, not safety_tolerability and not mixed); an efficacy-vs-placebo result alongside a not-superior-vs-active-drug result for the same key (the active comparison governs → ineffectiveness, not mixed); a governing efficacy endpoint alongside a positive secondary/exploratory endpoint (the governing endpoint governs — the secondary does not lift or conflict with it, so NOT mixed); multiple endpoints from one source with no category disagreement (this is a Pass D collapse, not a conflict — resolve to the governing endpoint, never mixed).
CONCLUSION CLASSIFICATION
Classify on the governing endpoint's result — the result of the single measure named in primary_endpoint, quoted as the evidence — not a summary of every endpoint the paper reports, and not the paper's general tone. Don't grade the trial's quality.
Do NOT pick one label out of nine in a single judgement — that is what makes the conclusion flip across runs. Answer the ordered fact-questions below and STOP at the first that fires. Gates 1–4 establish what KIND of readout exists; only if none fires do you reach step 5, where the efficacy label is COMPUTED from two independent facts (direction × comparator), never chosen as one of four. Step 6 (mixed) is a narrow last resort. This is a tree of facts, not a ranking of categories — no category is preferred.
1. no_results — Is there NO reported outcome of any kind (results not yet reported, protocol/design/rationale paper, ongoing/recruiting, terminated before any readout; signals: future tense "will enroll", registration/design language, no result numbers)? → no_results, primary_endpoint null. ANY data readout — even safety/PK/MTD — means NO here; go on.
2. safety_failure — Was the trial or an arm explicitly HALTED for AEs/toxicity/safety? → safety_failure. Mentioning AEs/DLTs/deaths on study does not qualify; a halt for recruitment/funding/futility does not qualify. (This is the "major safety" catch: it fires only on an actual stoppage, so a successful trial that merely reported adverse events passes through untouched — exactly the behaviour you asked for.)
3. safety_tolerability — Was efficacy NEVER assessed (the only readout is safety/tolerability/MTD/RP2D/dose-finding/PK-PD)? → safety_tolerability; primary_endpoint names the safety measure; polarity-neutral. If ANY efficacy result exists, NO; go on. (This gate is why a trial that DID measure efficacy is never diverted into a safety class.)
4. inconclusive — Was efficacy assessed but the governing-endpoint result genuinely UNRESOLVABLE (no clear verdict and no authors' conclusion on drug effect)? → inconclusive; still name the measure. Underpowering, no control, or no threshold are NOT triggers if a clear governing-endpoint verdict exists; that is NO, go on.
5. Efficacy axis — a resolvable efficacy verdict exists. COMPUTE the label from two independent facts; do not choose among the four directly:
(a) DIRECTION — from the governing endpoint's own quoted result and the authors' conclusion on it: did the drug succeed on that measure? → positive / negative.
(b) COMPARATOR (per COMPARATOR TYPE) — is the reference a distinct, named ACTIVE drug / standard-of-care agent (→ active), or placebo / none / historical / threshold / a strategy-intensity-target (→ inactive)?
(c) COMPOSE, no further judgement: positive + inactive → efficacy; negative + inactive → lack_of_efficacy; positive + active → effectiveness; negative + active → ineffectiveness. "Not better than / equivalent to / comparable to / no added benefit over" a named active drug is negative + active → ineffectiveness, never lack_of_efficacy.
6. mixed — ONLY if the key has two genuine co-primary endpoints pointing in OPPOSITE directions (name both, separated by "; "). This is the SOLE route to mixed. Several endpoints without directional conflict are collapsed to the governing endpoint in Pass D — never mixed. A failed primary plus a good secondary is NOT mixed (primary governs).
CONFIDENCE
- 0.95–1.0: verdict explicit ("met the primary endpoint," "terminated due to toxicity," "the MTD was X").
- 0.7–0.9: strongly implied, not explicit.
- below 0.7: genuinely unclear — don't inflate.
- Trial-level irrelevance row: confidence reflects how sure you are the abstracts are unrelated, not any drug verdict.
NORMALIZATION
- Therapy: core INN name only, no route/formulation/dose. Alphabetical within a regimen.
- Condition: most specific disease name stated; prefer a parenthetical's specific term. Subgroup-level names get their own condition only for a distinct disease entity (molecular subtype, distinct anatomical site) with per-subgroup results; use the umbrella term (e.g. "solid tumour") only for one pooled result across a mixed population. A clinical/demographic/treatment-pattern subgroup (age, dosing pattern, prior-treatment status) is NOT a condition — it goes in population and doesn't split the key.
- One name per disease trial-wide; renaming often reveals a hidden duplicate, so re-check.
- Keep a modifier only if it names a distinct disease entity (e.g. "triple-negative breast cancer"; split "tonsil and base-of-tongue cancer" into two). Drop etiology/comorbidity/severity/symptom modifiers ("breast cancer patients with loss of appetite" → "breast cancer").
- Synonyms: record other names the abstracts explicitly use (brand names, abbreviations, code names); omit if none.
EVIDENCE QUOTE
Exact verbatim span from one abstract, reporting the governing endpoint's result, with its source_pmid. One per outcome, and it must be about the governing measure named in primary_endpoint — not a secondary endpoint, and not what creates a row. (Exception: the trial-level irrelevance row uses a verbatim span from the trial description, source_pmid null.)
